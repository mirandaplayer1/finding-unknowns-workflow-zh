# 產出測驗（Quiz）

目的：只瀏覽成品只能得到淺層理解——很多關鍵藏在「為什麼這樣安排」和「動了這裡會影響哪裡」。交付前用測驗確認使用者真的理解這次的產出。

## 步驟

1. 讀本輪產出物的變更、`DECISIONS.md` 新條目、`notes/implementation-notes.md`。
2. 產出**單一互動 HTML 檔**（存 `notes/`）：上半部是變更報告，依序包含：
   - 心智模型：這次變更後，整個產出物的邏輯一句話怎麼說
   - 做了什麼、為什麼（連結到相關決策編號）
   - 牽動關係：這次的改動影響了既有內容的哪些部分（適合時用 SVG 圖示牽動關係）
   - 偏離計畫之處
3. 下半部是互動測驗，五到八題，選項可點選、交卷即時顯示對錯與簡短解說；底部放「複製作答結果」按鈕，把每題的作答與對錯輸出成結構化文字。題目涵蓋：
   - 至少一題考「為什麼選 A 不選 B」（對應 DECISIONS.md）
   - 至少一題考邊界情況（「如果受眾是 X／情境變成 Y，這個安排還成立嗎」）
   - 至少一題考影響範圍（「如果要改這一段，還有哪裡要跟著動」）
4. 使用者把作答結果貼回對話後，針對錯題深入講解，錯的地方回到產出物指給使用者看。每個錯題先診斷是哪一種、並說出是哪一種：（a）使用者的理解缺口→補講解；（b）產出物做得太繞→這是「該簡化」的訊號，不是使用者的錯。作答結果同時是 /reflect 的輸入（答錯處＝決策記錄不夠清楚的訊號）。
5. 全對才建議交付；沒全對就針對弱點補充講解後重出新題。同一主題連錯兩次→優先建議簡化或拆分該部分產出，不要繼續出題。
6. 全對後交棒：成果要給別人看、需要 buy-in → `/pitch`；不用就直接交付，之後開新對話跑 `/reflect`。

## 原則

- 題目考理解不考記憶：問判斷與因果，不問「第幾頁寫了什麼」。
- 解說時先給心智模型，再進細節。
- HTML 產出一律照 WORKFLOW.md〈HTML 產出與互動介面〉：內嵌留言層＋「複製結果」出口（現成片段 `notes/html-comment-layer.html`）。
