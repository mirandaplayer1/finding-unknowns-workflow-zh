# 盲點掃描（Blindspot Pass）

目的有兩層：（一）掃出使用者的「未知的未知」；（二）**教會使用者這個領域，讓他有能力下更好的指令**。掃描是手段，提升他的提問能力才是目的——下次他自己就能問對問題。

## 步驟

1. **定位起點**：讀 `SPEC.md` 與專案既有素材，並確認使用者對這個領域的經驗值——他說「我完全不懂 X」和「我做過類似的」會導向不同深度的教學。不確定就直接問。
2. **掃描未知的未知**：列出他可能完全沒考慮到的面向——領域慣例、常見坑、受眾預設期待、素材限制。必要時搜尋網路補足。
3. **領域速成教學**（本 skill 的核心，對應「教我調色」模式）：
   - **心智模型**：這個領域的運作邏輯一句話怎麼說、專家看一份作品時在看什麼。
   - **行話對照**：他需要知道的關鍵詞彙各是什麼意思——有對的詞，才下得出對的指令。
   - **「好」的判斷標準**：好與壞的差異在哪裡，最好給對比實例（找兩個例子並指出差在哪），讓他從「看不出差別」變成「看得出好壞」。
   - **常見失敗樣態**：新手最常掉的洞，以及看到什麼徵兆代表方向錯了。
4. **產出「更好的指令」示範**：把他原本的需求改寫成二到三個具體的指令範例，並解釋改在哪裡、為什麼——例如原本「幫我把影片調好看」改成「用 teal-orange 方向調色，膚色保持自然，對比拉高一階」。這是他可以直接複製使用、也可以模仿學習的。
5. **教學內容的呈現**：領域速成（第 3 步）與指令示範（第 4 步）合併做成**單頁 HTML 講義**（存 `notes/`）——SVG 圖解心智模型、行話對照表、好壞對比實例並排、每個指令範例附複製按鈕。給人讀的長內容用 HTML，不用長篇 markdown。
6. **回填與交棒**：新事實與判斷標準寫入 `SPEC.md`（判斷標準通常屬於驗收條件或參考範例）；屬於「已知的未知」的模糊處記入未知清單；清單若還有未解項目就回頭補跑 `/interview`，全數收斂後才開工。

## 原則

- 教學先於代工：遇到「他連好壞都分不出」的領域，先教到他能判斷，再開始產出——否則做再多版本他也選不出來。
- 教學深度配合用途：他要的是「能下指令、能驗收」，不是成為專家；速成到夠用即可，不要傾倒整個領域。
- 每次教學結束問一句：「現在你會怎麼重新描述你要的東西？」——他的重述就是學習成果的檢驗。
- HTML 產出一律照 WORKFLOW.md〈HTML 產出與互動介面〉：內嵌留言層＋「複製結果」出口（現成片段 `notes/html-comment-layer.html`）。
- 「這裡沒有重大盲點」是有效而且有價值的結果：不要為了交差硬列盲點——掰出來的盲點會浪費後續的訪談與注意力。
- 本 skill 到「回填規格、交棒」為止：未經使用者要求，不進入任何實作。
