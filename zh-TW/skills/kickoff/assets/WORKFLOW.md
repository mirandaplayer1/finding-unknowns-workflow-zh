# 專案常駐指示

## 檔案地圖（先看這裡）

本專案的記憶全部在檔案裡，分工如下：

- `SPEC.md`——規格，唯一真相來源。每次開工必讀；還是空白模板就先跑 `/kickoff`。
- `DECISIONS.md`——決策記錄，教學導向。有取捨的決定寫這裡。
- `notes/implementation-notes.md`——本輪計畫、進度、偏離記錄。工作流水帳，反思後歸檔。
- `notes/*.html`——給使用者看與操作的互動介面（問卷、講義、報告），拋棄式。
- 本檔（WORKFLOW.md）——工作規則，經根目錄 `CLAUDE.md` 的 `@WORKFLOW.md` import 自動載入。只有 `/reflect` 的晉升流程能修改。

流程順序：`/kickoff` 起草規格（做法未定時插跑 `/scout` 看業界怎麼解）→ `/interview`、`/blindspot` 收斂未知 → 實作計畫 → 實作 → `/quiz` 確認自己懂 →（要給別人看時 `/pitch` 要 buy-in）→ 新對話 `/reflect` 復盤。

## 規格是唯一真相來源

- 每次開工先讀 `SPEC.md`。所有產出以規格為準，不憑印象。
- **門檻：SPEC.md 尚未經我核可（還是空白模板、或標著大量「待確認」）時，不進入實作，先跑 `/kickoff` 完成規格。專案再簡單都一樣，簡單專案的規格可以只有幾句話。**
- 工作中發現規格與實際狀況衝突時（素材不如預期、限制比想像多、原本的做法行不通）：停下來，先在 `SPEC.md` 的「未知清單」記下衝突，向我確認或依保守原則決定，更新規格後才繼續改產出物。規格永遠比產出物先改。
- 對話接近需要壓縮（compaction）時，先把尚未沉澱的決定與發現寫進 `notes/implementation-notes.md` 與 `DECISIONS.md`，再讓壓縮發生。

## 決策記錄（教學模式）

我在跟著你學習，所以決策過程比結果重要：

- 凡是「有兩個以上合理選項」的決定，一律記入 `DECISIONS.md`，依該檔開頭的格式填寫，特別是「下次怎麼自己判斷」欄位。內容取捨、結構安排、呈現形式、工具選擇都算。
- 純機械性、無選擇餘地的步驟不用記，避免稀釋訊號。
- 遇到計畫外的狀況：選保守選項（可逆的、影響範圍小的），記入 `notes/implementation-notes.md` 的「偏離記錄」，繼續前進，不要卡住等我。
- 兩者的分工：偏離記錄記「發生了什麼、臨時怎麼處置」；若該偏離涉及實質取捨（有兩個以上合理選項），取捨本身記入 `DECISIONS.md`，偏離表引用其 D-編號，不要重複寫兩份。

## 工作筆記

- 動工前，先從 SPEC.md 推導「本輪計畫」寫入 `notes/implementation-notes.md`：步驟順序與完成檢查點，把最可能被推翻的決定放最前面讓我先看（資料結構、對外呈現、骨架調整這類；機械性步驟放最後）。簡單任務計畫可以只有兩三行；我確認後才執行。
- 大輪次（步驟多、需要示意圖或程式片段才講得清楚）把計畫升級成 HTML 實作計畫頁存 `notes/`：一樣是最可能改的決定放最前面。計畫核可後可以開新對話、把計畫頁與規格一起帶進去，讓乾淨的上下文執行實作。
- 每個工作階段維護 `notes/implementation-notes.md`：本輪計畫、目前進度、偏離記錄、待確認的未知。
- 這是工作層流水帳，允許雜亂；精煉是 `/reflect` 的工作，不是工作當下的工作。

## HTML 產出與互動介面

- 需要我「閱讀長內容、比較多個選項、回答一串問題」時，不要用長篇 markdown 或逐則訊息轟炸——產出**單一自包含 HTML 檔**（存 `notes/`），用視覺結構、表格、SVG 圖解呈現，超過百行的 markdown 我不會讀完。
- **互動迴路必須閉合**：你看不到我在瀏覽器裡的操作，所以每個互動式 HTML 結尾都要有「複製結果」按鈕，把我的選擇／作答輸出成結構化文字讓我貼回對話；收到後把結論沉澱到對應檔案。沒有出口的互動介面等於沒發生。
- **每個 HTML 都要能收我的意見，純閱讀的報告也不例外**（比較頁、講義、報告、檢核頁一律適用）：每個段落、卡片、步驟旁放一個可收合的留言框，頁尾放固定的「複製全部意見」按鈕，輸出格式為 `## 《標題》意見回饋` ＋ 每則 `### 段落名` 後接內容；留言用 localStorage 存著，重新整理不會消失。可直接複製的實作片段見 `notes/html-comment-layer.html`，內嵌進新頁面即可。我讀報告時的反應是最有價值的回饋，沒有留言欄就等於丟掉。
- **頁面照 ADHD 格式寫**：第一屏就是結論與下一步；多步驟編號；清單長就分組分層（現在做／之後做、必要／加分），不硬砍數量、不因簡潔丟掉重要訊息；細節一律收合、預設不展開。每頁只回答一個問題，塞不下就拆頁。
- 格式分工：markdown 留給恆在層與需要版本差異比對的檔案（SPEC、WORKFLOW、DECISIONS）；HTML 用於給我看、給我操作的介面（提案比較、問卷、報告、測驗、實作計畫、提案、拋棄式編輯器）。

## 溝通方式

- 用繁體中文。解釋決策時先給心智模型再給細節，指出取捨時直說，不迴避矛盾。
- 我問「為什麼」時，回答要讓我下次能自己判斷，而不是只給結論。

## 自我改進規則

- 本檔只收「同類教訓出現兩次以上」的規則，由 `/reflect` 流程晉升寫入，並附一行來源說明。
- 一次性的教訓留在 `notes/`，不要直接寫進本檔。
